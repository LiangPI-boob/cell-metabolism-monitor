# Checklist

> 说明：除“台架验证”分组外，以下条目均已通过源码核对与编译验证；台架分组需要两块实机，保持未勾选。

## 架构与网络

- [x] 主机固定工作在 `WIFI_AP_STA`，`NanoStatAP` 在 STA 连接成功/失败两种情况下都保持开启
- [x] 从机只做 STA，连接 `NanoStatAP`；从机没有 HTTP/WebSocket 控制入口
- [x] 主机在 3333 端口运行 TCP Server；从机作为客户端主动连接 `192.168.4.1:3333`
- [x] 主机只保留一个从机客户端，第二个连接被立即关闭
- [x] 网页只连接主机；泵/阀操作不依赖从机直连

## 协议与鉴权

- [x] `hello` 包含 `fw`、`channels`、`key`；key 正确才置在线，错误立即断开
- [x] `hello` 通过后主机下发 `status`，从机返回泵/阀真实状态完成对账
- [x] TCP 使用 JSON 行格式，`\n` 结尾，单行超过 512 B 被丢弃
- [x] `ping/pump/valve/stop_all/status/clear` 在 TCP 上的行为与 USB 串口一致
- [x] 响应携带与命令相同的 `id`

## 心跳与重连

- [x] 主机在链路在线期间（含 IDLE）每 5 s 发一次 `ping`
- [x] 从机 120 s 未收到命令进入安全态，且同一超时周期只上报一次 `E_NO_HEARTBEAT`
- [x] 从机断线后按 1/2/5/10/30 s 退避重连，15 s 内恢复
- [x] 主机在 socket 断开或 20 s 无消息时标记从机离线
- [x] 主机静测阻塞约 60 s 时 TCP 连接保持，从机不误判心跳超时

## 执行器安全

- [x] 主机循环泵命令使用 `circulate_ms + 60000` 的有限时长，不再发送 `ms=0`
- [x] 从机拒绝 `ms<=0` 的泵命令并返回 `E_PARAM`
- [x] 从机泵上限 1 h、阀上限 30 s 仍然生效
- [x] 从机网络写入不阻塞执行器定时；发送缓冲不足时丢弃本次 `hb`
- [x] 循环中断线后，泵在“循环时长 + 60 s”内停，阀 ≤ 30 s 关

## 网页状态

- [x] 主机通过 WebSocket 广播 `slave_link`，网页显示从机在线/离线
- [x] 从机离线时 `expStart()` 拒绝启动并给出提示
- [x] 原有实验阶段、周期、泵/阀状态显示不回退

## 仓库与文档

- [x] AP 密码、从机 Wi-Fi 密码、link key 位于不入库的凭据头文件，`.gitignore` 已覆盖
- [x] `README.md` 已删除不可实施的 UART 接线并改为 Wi-Fi 拓扑
- [x] `docs/开发方案.md` §2.4、`docs/软件需求说明书.md`、`docs/项目进度总结.md` 已同步
- [x] 主机运行时不再依赖 `Serial2`；GPIO25/26/27 分配未改变
