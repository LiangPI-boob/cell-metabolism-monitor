## 一、项目目标与软件范围

### 1.1 一句话目标

让系统能**无人值守自动跑完一次 12~72 h 的细胞代谢监测实验**，并按协议输出"准连续"的葡萄糖/乳酸浓度动态曲线。

### 1.2 软件要解决的核心问题

| # | 问题 | 软件对策 |
|---|------|----------|
| 1 | 实验要连续跑几十小时，人不能一直守着 | **自动调度状态机**：按协议循环执行「循环→停流→静测→校准」 |
| 2 | 电极会漂移，长时定量不可信 | **在线自校准**：周期性切标准液，自动更新灵敏度/截距 |
| 3 | 泵阀动作与电化学采集相互干扰 | **采集与动作分时**：静测窗口内泵阀全停 |
| 4 | 数据要能看、能存、能出报告 | **网页 UI + 数据分析 + 导出** |
| 5 | 出问题要知道 | **告警 + 远程查看（AIoT）** |

### 1.3 本需求覆盖范围

| 模块 | 覆盖 | 说明 |
|------|------|------|
| 从机（流体控制板）固件 | ✅ | 泵阀驱动、安全联锁、JSON 行协议（Wi-Fi TCP） |
| 主机（NanoStat）调度软件 | ✅ | 状态机、协议调度、采集、校准算法 |
| 网页 UI | ✅ | 实时曲线、控制、参数设置 |
| 数据分析与导出 | ✅ | 峰检测、基线扣除、CSV/图导出 |
| 云端 AIoT | ⏳ | P4 阶段，本版仅预留接口 |

### 1.4 不在本需求范围

- 硬件接线与机械结构（见《硬件交接单.md》）
- 芯片/检测模块的加工（见《芯片设计说明书.md》）
- 生物实验方案本身（细胞培养、加药设计）

## 二、软件系统架构

```
[手机 / PC 浏览器]
        ⇅ Wi-Fi (WebSocket / HTTP)
┌──────────────────────────────────────────────┐
│ 主机：NanoStat（ESP32）                        │
│  ├─ 电化学采集（LMP91000，现有）                │
│  ├─ 实验调度状态机（本次新增，核心）              │
│  ├─ 网页服务 + WebSocket（现有，需扩展）         │
│  └─ TCP 协议调度 ──┐                          │
└─────────────────────┼────────────────────────┘
                      │ JSON 行协议，Wi-Fi TCP 3333
┌─────────────────────┼────────────────────────┐
│ 从机：流体控制板（ESP32）                       │
│  ├─ 循环泵（GPIO25）                           │
│  ├─ 切换阀（GPIO26）                           │
│  ├─ 排废阀（GPIO27）                           │
│  └─ 安全联锁（超时/心跳/急停）                   │
└──────────────────────────────────────────────┘
```

**分工原则**
- **主机**：决定"什么时候做什么"（调度）+ 采集 + 给人看
- **从机**：只负责"把动作安全执行到位" + 本地保护
- 两者只通过**Wi-Fi TCP 上的 JSON 行协议**耦合，可各自独立开发、独立测试

## 三、功能需求（FR）

### FR-1 实验流程调度（★核心）

**描述**：按预设协议自动循环执行实验周期，全程无需人工干预。

**状态机**

```
        ┌──────────────────────────────────────────┐
        │                                          │
        ▼                                          │
     [IDLE] ──开始实验──► [CIRCULATE] ──► [STOP_FLOW] ──► [MEASURE]
        ▲                    ▲                                │
        │                    │                                │
        │                    │                        读数完成 │
        │                    │                                ▼
        │                    │                     ┌──────────────────┐
        │                    │                     │ 到了校准周期？     │
        │                    │                     └────┬────────┬────┘
        │                    │                     否   │        │ 是
        │                    │                          │        ▼
        │                    └──────────────────────────┘   [CALIBRATE]
        │                                                       │
        └───────────────── 实验结束 / 用户停止 ──────────────────┘
```

**各状态定义**

| 状态 | 泵 | 阀 | 目的 | 默认时长 |
|------|-----|-----|------|----------|
| `IDLE` | 停 | 关 | 待机 | — |
| `CIRCULATE` | 开（低速） | 关 | 均质下腔、冲洗电极表面 | 5~10 min |
| `STOP_FLOW` | 停 | 关 | 膜上下跨膜平衡 | 5~15 min |
| `MEASURE` | 停 | 关 | 安培法采样，出 1 个浓度点 | 30~60 s |
| `CALIBRATE` | 停 | 切换阀开 | 标准液标定，更新灵敏度 | 3~5 min，每 6 h |

**验收点**
- [ ] 能从 `IDLE` 一键启动，自动跑完 ≥ 3 个完整周期
- [ ] 每个状态的**实际时长**可配置，且与设定值误差 ≤ 5%
- [ ] 校准按周期自动触发，无需人工
- [ ] 任意时刻可"停止实验"，系统回到 `IDLE` 安全态

---

### FR-2 电化学采集

**描述**：在 `MEASURE` 窗口内完成一次安培法测量，得到一个浓度点。

**需求**
- 静测期间泵阀**必须全停**（见 FR-1），避免流场扰动读数
- 采样窗口 30~60 s，取稳定段均值作为该点电流
- 由电流 → 浓度：用**最近一次校准**的灵敏度/截距换算
- 每个浓度点附带时间戳、状态标记（正常/校准/异常）

**验收点**
- [ ] 单点测量可在 60 s 内完成
- [ ] 输出 (时间, 电流, 浓度) 三元组，写入本地记录

---

### FR-3 在线自校准

**描述**：周期切换标准液，自动更新标定曲线，补偿电极漂移。

**流程**
1. 切换阀切到**标准液支路**
2. 泵推动标准液流过电极流道
3. 采集标准液读数
4. 计算新的灵敏度/截距，更新标定参数
5. 切换阀切回**循环支路**，排废阀排掉残液
6. **确保标准液不回流细胞腔**（安全隔离，不可妥协）

**验收点**
- [ ] 校准可自动触发，也可手动触发
- [ ] 校准记录可追溯（时间、斜率、截距、漂移量）
- [ ] 校准期间细胞腔不受影响（阀隔离有效）

---

### FR-4 网页 UI

**描述**：浏览器端实时查看与控制。

**页面需求**

| 页面 | 功能 |
|------|------|
| **实时监测** | 浓度/电流曲线实时刷新；当前状态（处于哪个阶段）；剩余时间 |
| **控制** | 启动/停止实验；手动开泵/开阀（调试用） |
| **参数设置** | 各阶段时长、校准周期、泵速、采样窗口 |
| **历史记录** | 按实验列出历史曲线，可回看/重命名/删除 |
| **数据分析** | 多曲线叠加、缩放游标、峰检测、基线扣除、均值/标准差 |
| **导出** | CSV 导出、曲线图导出 |
| **系统** | 设备状态、日志、缓存清理 |

**验收点**
- [ ] 网页无需安装，手机/PC 浏览器直接打开
- [ ] 曲线刷新延迟 ≤ 2 s
- [ ] 所有页面在手机竖屏下可正常使用

### FR-7 告警

| 告警类型 | 触发条件 | 通知方式 |
|----------|----------|----------|
| 从机故障 | 收到 `evt:"fault"` | 网页弹窗 + 曲线标注 |
| 从机离线 | 主机 20 s 未收到从机任何消息（主机每 5 s 发 `ping`） | 网页 `slave_link` 置 `offline` + 尝试恢复；此时拒绝启动实验并广播 `{"exp_error":"slave_offline"}` |
| 心跳丢失（从机侧） | 从机 120 s 未收到任何命令 | 从机进安全态（泵停、阀回安全位）并上报一次 `{"evt":"fault","code":"E_NO_HEARTBEAT"}` |
| 数据异常 | 电流超量程 / 突变超阈值 | 标记该点，继续实验 |
| 实验完成 | 到达设定时长 | 网页提示 |

## 四、与硬件的接口需求（★ 对接同学）

> 本节是软件对**从机流体控制板**提出的明确要求，请硬件/固件侧按此实现。

### 4.1 通道约定

| 通道号 | 执行器 | GPIO | 说明 |
|--------|--------|------|------|
| 泵 0 | 循环泵 | `GPIO25` | 支持 PWM 调速 |
| 阀 0 | 切换阀 | `GPIO26` | 开 / 关 |
| 阀 1 | 排废阀 | `GPIO27` | 开 / 关 |

- 驱动模块为**高电平触发**（已实测），固件中 `HIGH` = 导通
- 上电默认态：泵停、阀关（常闭阀断电即安全位）

### 4.2 通信协议（Wi-Fi TCP）

物理层：2.4 GHz 802.11 b/g/n；主机 `WIFI_AP_STA`，常开 SoftAP `NanoStatAP`（密码 `AP_PASSWORD`）+ TCP Server `192.168.4.1:3333`；从机 STA 连该 AP 后作为 TCP Client 连 `192.168.4.1:3333`，单客户端。应用层为 JSON 行协议（`\n` 结尾，单行 ≤512 B），与 USB 调试串口共用同一套命令。

**命令（主机 → 从机）**

| 命令 | 示例 | 说明 |
|------|------|------|
| 心跳 | `{"cmd":"ping"}` | 主机每 5 s 发一次 |
| 泵 | `{"id":1,"cmd":"pump","ch":0,"speed":50,"ms":60000}` | 通道0，50% 速度，运行 60 s；`ms` 必须为正数，上限 3600000 |
| 阀 | `{"id":2,"cmd":"valve","ch":0,"state":"open"}` | `state` ∈ `open`/`close` |
| 全停 | `{"id":3,"cmd":"stop_all"}` | 软急停 |
| 状态 | `{"id":4,"cmd":"status"}` | 查询快照 |
| 清故障 | `{"id":5,"cmd":"clear"}` | 从 FAULT 恢复 |

**响应（从机 → 主机）**

```json
{"id":1,"ok":true}
{"id":2,"ok":false,"err":"E_PARAM","msg":"speed out of range"}
```

**事件上报（从机主动）**

```json
{"evt":"hello","fw":"p1-0.1","channels":{"pump":1,"valve":2},"key":"<SLAVE_LINK_KEY>"}
{"evt":"boot","fw":"p1-0.1","channels":{"pump":1,"valve":2}}
{"evt":"fault","code":"E_NO_HEARTBEAT"}
{"evt":"hb","state":"IDLE","uptime_ms":123456}
```

> 从机连上 TCP 后先发 `hello`；主机校验其中的 `key` 与 `SLAVE_LINK_KEY` 一致，不一致即断开。

**错误码**

| 码 | 含义 |
|----|------|
| `E_PARAM` | 参数越界 |
| `E_BAD_CMD` | 未知命令 |
| `E_BUSY` | 当前状态不允许 |
| `E_FAULT` | 处于故障态 |
| `E_NO_HEARTBEAT` | 心跳超时 |
| `E_ESTOP` | 急停触发 |

### 4.3 对硬件的非功能要求

| 项 | 要求 |
|----|------|
| 命令响应时间 | ≤ 100 ms（收到命令到开始动作） |
| 心跳超时 | 主机每 5 s 发 `ping`；从机 120 s 未收到任何消息 → 进入安全态并上报；主机 20 s 未收到从机消息 → 判从机离线 |
| 链路鉴权 | 从机连上后发 `hello`（含 `fw`/`channels`/`key`），主机校验 `key == SLAVE_LINK_KEY` |
| 阀最长通电 | 固件内硬限制 **30 s**（防线圈过热） |
| 泵参数范围 | `speed` 0~100（%），`ms` 1~3600000 |
| 断电行为 | 所有输出自动进入安全态（泵停、阀关） |
| 独立自测 | 不接主机时，可用 TCP 工具或串口助手完成全部动作测试 |

## 六、可靠性与安全需求

| 项 | 要求 |
|----|------|
| 看门狗 | 主机、从机均启用任务/硬件看门狗 |
| 心跳机制 | 主机每 5 s 一次 `ping`；从机 120 s 超时进安全态；主机 20 s 无消息判从机离线 |
| 急停 | 物理按钮 + 软件 `stop_all`，两者等效 |
| 故障恢复 | `clear` 命令可在故障消除后回到 `IDLE` |
| 数据不丢 | 长实验中途断电，已采集数据不丢失 |
| 非阻塞设计 | 主循环不得使用阻塞式 `delay()` 做长等待 |

## 七、验收标准（Definition of Done）

**从机固件**
- [ ] 通过 TCP 或串口发命令，泵/阀动作与响应一致
- [ ] 断开心跳后自动进入安全态
- [ ] 连续 24 h 泵阀循环测试无死机
- [ ] 非法命令被拒绝并返回错误码

**主机软件**
- [ ] 一键启动后自动跑完 ≥ 3 个完整周期
- [ ] 校准按周期自动触发且记录可追溯
- [ ] 曲线实时刷新、历史可回看、数据可导出

**系统联调**
- [ ] 泵阀动作时电化学基线噪声在可接受范围（电磁干扰测试）
- [ ] 完整跑通一次「循环→停流→静测→校准」并输出浓度曲线
