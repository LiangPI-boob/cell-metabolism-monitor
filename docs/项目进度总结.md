## 一、项目是什么

**一句话**：做一台能**自动养细胞 + 自动测代谢指标（葡萄糖/乳酸）**的准连续监测系统。

**核心原理**
1. 细胞在多孔膜（PC 0.4μm）上静置培养
2. 代谢物透过膜扩散进「膜下小体积腔」（约 78 μL）
3. 下腔与独立检测模块用软管**闭环循环**
4. 停流静测（安培法）+ 每 6 小时**在线自校准**
5. 覆盖 **12~72 小时无人值守**

**系统架构（双 MCU）**

```
[手机/PC 浏览器] ⇄ Wi-Fi ⇄ [主机 NanoStat (ESP32-PICO-D4 + LMP91000)]
                              ├─ 电化学采集（ADC/C1/C2/DAC）
                              ├─ 网页 :80 + WebSocket :81
                              ├─ 实验调度状态机（本机执行，不依赖 PC）
                              └─ SoftAP「NanoStatAP」+ TCP Server :3333
                                        ⇅ JSON 行协议（Wi-Fi）
                                 [从机 ESP32 流体控制板]
                                  ├─ 循环泵 → GPIO25
                                  ├─ 切换阀 → GPIO26
                                  └─ 排废阀 → GPIO27
```

### 4.2 从机固件 ✅ 已烧录并联网

**文件**：`slave/slave_firmware/slave_firmware.ino`（v1.2，约 350 行）

**硬件配置**

| 执行器 | 引脚 | 通道号 |
|---|---|---|
| 循环泵 | GPIO25 | pump ch 0 |
| 切换阀 | GPIO26 | valve ch 0 |
| 排废阀 | GPIO27 | valve ch 1 |
| 接主机 | Wi-Fi STA → TCP Client `192.168.4.1:3333` | — |

**关键实现**
- **双通道**：USB Serial（调试）+ Wi-Fi TCP（接主机）；两个通道都能收命令，响应回到发命令的通道。`Serial2`（GPIO32/33）仅台架备用，**非运行链路**
- **驱动模块高电平触发**（已验证）：`HIGH` = 导通
- **安全保护**：心跳超时 **120 s** → 停泵关阀并上报（`g_safeLatched` 保证**只报一次**）；阀最长 **30 s**；泵单次最长 **1 h**；上电默认泵停阀关
- **断线重连**：退避 1 / 2 / 5 / 10 / 30 s；`WiFi.setSleep(false)`、`setAutoReconnect(true)`、`setNoDelay(true)`
- **半行缓冲修复**：TCP 刚断开会清空 `g_rxLineTcp`，避免重连后新旧半行拼接导致 `E_BAD_CMD`
- 非阻塞设计（全程 `millis()`）

**JSON 行协议（一行一个 JSON，`\n` 结尾，≤512 B）**

```json
{"cmd":"ping"}
{"id":1,"cmd":"pump","ch":0,"speed":50,"ms":60000}
{"id":2,"cmd":"valve","ch":0,"state":"open"}
{"id":3,"cmd":"stop_all"}
{"id":4,"cmd":"status"}
{"id":5,"cmd":"clear"}
```

响应 `{"id":1,"ok":true}` / `{"id":2,"ok":false,"err":"E_PARAM","msg":"..."}`；事件 `{"evt":"boot",...}`、`{"evt":"hb","state":"IDLE","uptime_ms":...}`、`{"evt":"fault","code":"E_NO_HEARTBEAT"}`、`{"evt":"hello","fw":"slave-1.2","key":"...","channels":{"pump":1,"valve":2}}`

**验证结果**：USB 串口正常输出 `boot` 与 5 s 一次 `hb`；已连上主机 AP 并通过 `hello` 鉴权，主机侧显示在线。

## 五、踩过的坑 & 解决方案（**重要，别重复踩**）

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| 1 | 串口日志反复停在 `BOOT: LMP init done`、看着像启动崩溃/重启循环 | **CP210x 自动复位电路（DTR=GPIO0，RTS=EN）**：每次打开串口都会拉低 EN 复位；监控工具反复开关端口就会刷出一串 `rst:0x1 (POWERON_RESET)` | 这是**假象**。一次打开端口、持续监听即可看到完整启动日志；判板子好坏请看热点是否出现、LED 是否闪 15 次 |
| 2 | `netsh wlan show networks` 看不到 `NanoStatAP` | 无线网卡当前连着别的 SSID 时，扫描结果不全/滞后 | 用手机看热点，或先把电脑切到别的网络再扫；**不能据此判定 AP 没起来** |
| 3 | `uploadfs` 后校准系数丢失 | SPIFFS 被整块擦除（`0x290000`，1.44 MB） | 重烧前先 `GET /calibration.JSON` 备份，放进 `data/` 一起烧上去，烧完再删本地副本 |
| 4 | 从机编译报 `#error 缺少 wifi_secrets.h` | 凭据文件不入库，clone/清理后会缺 | 从 `.example.h` 复制并填真实值；`SLAVE_WIFI_PASS` = 主机 `AP_PASSWORD`，`SLAVE_LINK_KEY` 两端一致 |
| 5 | 两块板都是 CP210x，容易烧错 | 同型号、端口号会变 | **按序列号区分**：`0001`=从机、`02DA3ECE`=主机；烧前先 `pio device list` |
| 6 | 主机插上电脑但设备管理器没有 CP210x | 线只供电不传数据 / 口不通 / 接头没插到位 | 换数据线、换机箱后面板 USB 口；插上应有系统提示音 |

## 六、当前卡点：泵不受 ESP32 控制（已定位为电平问题）

| 测试 | 结果 | 结论 |
|---|---|---|
| 泵两根线直接接 5V | 泵转 | 电源、面包板电源轨、泵正常 |
| 驱动模块 SIG 用杜邦线碰 5V | 泵转 | 驱动模块、接线正常 |
| ESP32 GPIO25 → 模块 SIG，发 pump 命令 | 串口回 `ok:true`，泵不转 | **3.3V 输出不足以触发「5V 高电平触发」模块** |
| ESP32 GND ↔ 面包板蓝轨 | 已接 | 共地没问题 |

**结论**：软件/协议没问题，问题在 **3.3V → 5V 电平**。
**解决**：买 3.3V→5V 电平转换模块（BSS138 四路小板）或换 3.3V 兼容/带光耦的驱动模块。

## 九、给下一个对话 / 下一个 AI 会话的提示

1. **先读本文件，再读 `docs/主从WiFi通信开发文档.md`**，后者有完整协议、时序参数和各改造点代码位置。
2. 用户是软件负责人，**编程基础不深**：解释要通俗，给「点哪里 / 敲什么命令」的级别，避免堆术语。
3. **两块独立的 ESP32 板**，引脚重复正常；板间链路走 Wi-Fi，**不占任何 GPIO**（UART 方案因主机 PCB 无排针已废弃）。
4. **烧录前必须按序列号认板**：COM5=`0001`=从机，COM6=`02DA3ECE`=主机。端口号会变，序列号不会。
5. **不要把"串口日志停在 LMP init"当成崩溃**：那是 CP210x 自动复位在反复拉 EN。判定板子是否正常，看热点 `NanoStatAP` 是否出现、LED 是否闪 15 次。
6. 验证链路最快的办法（不改代码、不动执行器）：
   - `GET http://nanostat.local/netinfo` 看 `sta_connected` 与 `ap_clients`
   - 连 `ws://<主机IP>:81/` 读一帧状态，看 `"slave_link":"online"`
7. **不要用 `uploadfs` 当日常操作**：会擦掉 SPIFFS 里的 `/calibration.JSON`；只改网页时才需要。
8. 当前最紧急的硬件问题是 **3.3V→5V 电平**，不是软件；不要试图用改代码解决泵不转。
9. 改动前先确认 `git status`，凭据文件（`wifi_credentials.h`、`wifi_secrets.h`）已加入 `.gitignore`，**不要提交**。
