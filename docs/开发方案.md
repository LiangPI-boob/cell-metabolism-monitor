# 细胞代谢在线监测系统 —— 开发方案（P1：流体控制从机）

> 版本：v0.1（草案）
> 日期：2026-09-13
> 范围：**P1 详细设计**（从机 ESP32 固件 + 蠕动泵/电磁阀驱动 + 串口协议）；P2–P4 仅给出概要。
> 目标项目：膜隔离静置培养 + 下腔闭环微循环的细胞代谢（葡萄糖/乳酸）在线监测平台。

---

## 0. 背景与本方案要解决的问题

项目科学目标：用「上腔静置培养 + 下腔闭环微循环」实现细胞代谢的**原位、实时、无损、12~72h 无人值守**监测。检测端复用现有 NanoStat（ESP32 + LMP91000）方案，流路与调度由新增的控制系统承担。

创新点对控制系统的硬性要求：

| 创新点 | 对控制系统的要求 | 落点 |
|--------|------------------|------|
| ① 膜隔离静置培养 + 下腔闭环微循环 | 循环泵维持下腔闭环流动；培养腔不被扰动 | P1（执行器）+ P2（调度） |
| ② 培养芯片与检测模块物理分离 + 快插 | 流路可隔断，电极模块可在线更换不中断培养 | P1（阀）+ P2（流程） |
| ③ 校准液与细胞绝对隔离 | 三通阀切换检测/校准；校准残液独立排废不回流 | P1（阀拓扑）+ P2（流程） |
| ④ AIoT 闭环调度 + 无人值守 | 自动执行「循环均质→停流平衡→静测读数→周期校准」；按趋势自适应校准间隔；异常告警 | P2 起（P1 提供安全执行底座） |

**P1 的定位**：先把"能安全、可靠、可独立测试地驱动泵和阀"这件事做扎实，并定义好与主机的串口协议。P1 完成后，从机可在**不接主机**的情况下用串口助手完成全部动作自测。

## 1. 系统总体架构（双 MCU）

```
[手机/PC 浏览器] ⇄ Wi-Fi ⇄ [主机：NanoStat ESP32]
                             ├─ LMP91000 电化学采集（现有 src/main.cpp）
                             ├─ 网页 + WebSocket（现有 data/）
                             └─ UART（JSON 行协议，115200）⇄ [从机：控制 ESP32]
                                                                 ├─ 蠕动泵 ×N（循环 / 加药 / 校准）
                                                                 ├─ 检测⇄校准 切换阀
                                                                 ├─ 排废阀
                                                                 └─（可选）流量/液位/温度传感器
```

- **主机（NanoStat）**：采集 + 网页 + **协议调度**。决定何时循环、停流、读数、校准，向从机下发动作指令。
- **从机（新增控制板）**：**动作执行 + 本地安全联锁**。驱动泵/阀、超时保护、故障上报。
- 分工理由：电化学采集对实时性敏感，流体驱动对时序/功率敏感；混在同一 MCU 上会相互干扰。分离后各自可独立升级、独立调试、独立供电。

## 2. P1：从机控制系统详细设计

### 2.1 P1 目标与验收标准

**目标**：交付一块可独立运行的流体控制从机，具备：
1. 驱动 N 路蠕动泵（PWM 调速 / 定时运行 / 急停）
2. 驱动检测⇄校准切换阀、排废阀（安全态可定义）
3. 具备超时、心跳、看门狗、急停等安全联锁
4. 通过串口 JSON 行协议与主机通信，协议可扩展
5. 可脱机自测

**验收标准**：
- 串口发送命令，泵/阀动作与状态回报一致，误差在可接受范围
- 断开主机心跳后，从机自动进入安全态（泵停、阀回安全位）
- 连续 24h 泵/阀循环测试无死机、无失控（看门狗未误触发）
- 非法命令/超范围参数被拒绝并返回明确错误码

**P1 不含**：主机侧调度逻辑、网页改动、传感器闭环、上云（分别属 P2/P3/P4）。

### 2.2 从机硬件设计

#### 2.2.1 核心器件

| 项 | 选型建议 | 说明 |
|----|----------|------|
| MCU | ESP32-WROOM-32E 模组（或 ESP32-S3） | 与主机同生态；GPIO/PWM 充足；预留 Wi-Fi 可日后独立成网关 |
| 调试口 | USB 转串口（CH340/CP2102） | 用于烧录与串口自测 |
| 主机通信 | 独立 UART（TX/RX/GND） | 与调试口分离，便于同时调试 |
| 电源输入（P1） | USB 5V（适配器 / 充电宝） | 执行器全部选 5V 型，统一走 USB 5V 母线 |

> 主机 NanoStat 主机（含 ESP32 + LMP91000）已有一套，本清单只需再采购从机部分。

#### 2.2.2 电源架构（统一 USB 5V 母线：适配器 / 充电宝可对换）

```
USB 5V 输入（适配器 5V/2A  或  充电宝 5V/2A）
 ├─ 保险丝 + 防反接
 ├─ 5V 母线 ──→ 蠕动泵（5V，经驱动 MOS）
 │              └─→ 电磁阀（5V，经驱动 MOS，就近加滤波电解电容）
 └─ 5V ──→ ESP32 开发板板载 LDO ──→ 3.3V 逻辑
```

- 电源入口统一为 **USB 5V 母线**：调试时插**适配器**，便携/无人值守时插**充电宝**；两者都是 5V，**直接对换，硬件与固件均无需改动**。
- P1 全部执行器选 **5V 型**，直接用 USB 5V 供电，简化电源与接线。
- **功率地与逻辑地单点共地**，必要时对泵/阀加 LC 滤波、磁珠，抑制对电化学采集的干扰（P2 联调重点）。
- 泵与逻辑分开走线，避免电机启动瞬间拉低电压导致 MCU 复位。
- 电流预算与取电建议见 2.7。

**电池供电（备选方案）**

若需长期脱离市电，有三种方案；P1 建议直接用 ①（零改动）。

| 方案 | 接法 | 优点 | 缺点 |
|------|------|------|------|
| ① USB 充电宝（推荐） | 充电宝 5V/2A → USB 线 → 从机 | 即插即用，零设计改动；自带保护与充电管理 | 体积大；有"小电流自动断电"风险 |
| ② 单节 18650 + 5V 升压模块 | 18650 → 保护板 → 升压到 5V | 紧凑、容量大、可换电 | 需自建升压 + 保护 + 充电 |
| ③ 2S 锂电 7.4V + 降压 5V | 2 节串联 → BMS → 降压 5V | 效率高 | 最复杂，P1 不必要 |

三个注意点：

1. **充电宝"小电流自动断电"**：部分充电宝检测到负载电流过小（如 <50 mA）会关机，可能被 ESP32 待机电流触发 → 选支持"小电流模式 / 常供电"的充电宝，或维持一个持续的小电流负载。
2. **续航取决于泵阀占空比**，而非峰值电流。流程为"循环均质 → 停流平衡 → 静测读数"，泵阀间歇工作。以 10000 mAh 充电宝（5V 端可用约 6 Ah）估算：

   | 平均电流 | 大致续航 |
   |----------|----------|
   | 0.2 A | ~30 h |
   | 0.5 A | ~12 h |
   | 1 A（泵阀几乎常开） | ~6 h |

   要撑满 72 h，需加大容量或优化流程降低占空比。
3. **DC-DC 开关噪声**：方案 ②/③ 的升压/降压模块会引入高频噪声，可能干扰 LMP91000 采集 → 升压后加一级 LDO 或 LC 滤波；方案 ① 输出较干净，风险最小。

#### 2.2.3 执行器驱动

**蠕动泵（每路一套低边开关 + PWM 调速）**

| 环节 | 建议 |
|------|------|
| 开关 | N 沟道 MOSFET（**逻辑电平**型，小电流如 AO3400 / 较大电流如 IRL540N） |
| 续流 | 与泵并联的肖特基/快恢复二极管（如 1N5819 / 1N4007） |
| 栅极 | 串栅极电阻 + 下拉电阻（防浮空误导通） |
| 调速 | ESP32 LEDC PWM（建议 20 kHz，避开可听噪声） |
| 电流检测（可选） | 低边分流电阻 + 运放/INA 模块 → ADC，用于空转/堵转检测 |

> 若泵为成品"带驱动调速泵"，可直接用 PWM/串口调速，省去功率级；最终以采购实物为准。

**电磁阀（检测⇄校准切换阀、排废阀）**

| 环节 | 建议 |
|------|------|
| 开关 | 低边 MOSFET（或继电器模块），线圈反电动势**必须**加续流二极管 |
| 隔离 | 可选光耦隔离，进一步隔离线圈干扰 |
| 默认态 | 建议选**常闭（NC）**型，断电即回安全位 |
| 拓扑实现 | 优先用 **2 个二位二通阀**组合实现"检测/校准"切换，比选型二位三通更易采购、更易维护 |

**可选传感器接口（P1 预留，不阻塞）**：1-Wire（DS18B20 温度）、I2C、ADC 各预留一组排针。

#### 2.2.4 保护与接插件

- 电源防反接、保险丝、TVS、**物理急停按钮**（接 GPIO，独立于软件）
- 泵/阀一律用**可插拔端子**（凤凰端子 / JST-XH），便于更换与故障隔离
- 预留状态 LED（运行/故障/心跳）

### 2.3 从机固件设计

#### 2.3.1 模块划分

| 模块 | 职责 |
|------|------|
| `comm` | UART 收发行缓冲、JSON 解析/序列化，**非阻塞** |
| `actuators` | 泵/阀抽象：`Pump.setSpeed(pct)` / `Pump.stop()`；`Valve.set(state)` |
| `safety` | 看门狗、命令超时、心跳超时、急停、电流异常 |
| `state` | 状态机与状态快照，供 `status` 命令与事件上报 |
| `sequencer` | （P2 预留）复合动作序列执行 |

#### 2.3.2 状态机

```
BOOT → IDLE ──(收到动作命令)──→ RUNNING
         ↑                        │
         └────(动作完成/停止)──────┘
         │
         └──(急停/心跳超时/故障)──→ FAULT ──(clear 命令 + 条件恢复)──→ IDLE
```

- `FAULT` 状态下所有输出进入**安全态**：泵停、阀回安全位、拒绝除 `status`/`clear`/`stop_all` 外的命令。
- 所有动作时序用 `millis()` 计时，**禁止**在动作路径使用阻塞式 `delay()`。

#### 2.3.3 安全联锁

1. **命令级超时**：每条泵命令必须带 `ms`，且有上限（防止无限运行）；`ms=0` 表示"常开"，仅允许在明确指令下使用。
2. **心跳**：主机每 2 s 发 `ping`；从机 8 s 未收到任何命令 → 进入安全态并上报 `E_NO_HEARTBEAT`。
3. **看门狗**：启用 ESP32 硬件/任务看门狗。
4. **急停**：物理按钮 + `stop_all` 命令软急停，两者等效。
5. **电流异常（可选）**：泵电流超阈值判定堵转/空转 → 停止该路并上报。

#### 2.3.4 动作原语

| 原语 | 语义 |
|------|------|
| `pump` | 指定通道以某速度运行某时长（或常开） |
| `valve` | 指定阀开/关/切换 |
| `stop_all` | 全部停止，阀回安全位 |
| `status` | 返回全部泵/阀/状态快照 |
| `clear` | 从 `FAULT` 恢复到 `IDLE`（需故障条件已消除） |

### 2.4 串口通信协议（P1 定稿）

- **物理层**：UART，115200，8N1，3.3V 电平；主机 TX→从机 RX，主机 RX←从机 TX，共地。
- **帧格式**：一行一个 JSON 对象，以 `\n` 结束。命令带 `id`，响应回带同一 `id` 以便匹配。
- **命令（主机 → 从机）**

| 命令 | 示例 | 说明 |
|------|------|------|
| ping | `{"cmd":"ping"}` | 心跳 |
| 泵 | `{"id":1,"cmd":"pump","ch":0,"speed":50,"ms":60000}` | 通道0，50% 速度，运行 60 s；`ms=0` 常开 |
| 阀 | `{"id":2,"cmd":"valve","ch":1,"state":"open"}` | `state` ∈ `open`/`close` |
| 全停 | `{"id":3,"cmd":"stop_all"}` | 软急停 |
| 状态 | `{"id":4,"cmd":"status"}` | 查询快照 |
| 清故障 | `{"id":5,"cmd":"clear"}` | 从 FAULT 恢复 |

- **响应（从机 → 主机）**

```json
{"id":1,"ok":true}
{"id":2,"ok":false,"err":"E_PARAM","msg":"speed out of range"}
```

- **事件上报（从机主动，无 id）**

```json
{"evt":"boot","fw":"p1-0.1","channels":{"pump":2,"valve":2}}
{"evt":"fault","code":"E_NO_HEARTBEAT"}
{"evt":"hb","state":"IDLE","uptime_ms":123456}
```

- **错误码表**

| 码 | 含义 |
|----|------|
| `E_PARAM` | 参数越界/非法 |
| `E_BAD_CMD` | 未知命令 |
| `E_BUSY` | 当前状态不允许该命令 |
| `E_FAULT` | 处于 FAULT 态 |
| `E_NO_HEARTBEAT` | 心跳超时 |
| `E_ESTOP` | 急停触发 |
| `E_PUMP_OC` | 泵过流/堵转（可选） |

- **兼容性约定（面向 P2）**：所有命令保留 `cmd` 与 `id` 字段；响应统一 `ok`/`err`；新增能力通过新增 `cmd` 实现，不改动既有语义。

### 2.7 P1 采购清单（USB 5V 供电版）

> 前提：主机 NanoStat 已有一套，不再采购；本清单只为**从机控制系统**配套。
> 数量为最小可跑通版本，可按流路实际路数增减。

| # | 物料 | 数量 | 建议规格 | 备注 |
|---|------|------|----------|------|
| 1 | 从机主控 | 1 | ESP32-WROOM-32E DevKit（或 ESP32-S3 DevKit） | 板载 USB 转串口，直接烧录/自测 |

| 6 | 电源滤波电容 | 3–5 | 电解电容 100–470 µF / 耐压 ≥16V | 就近并在每个阀/泵处，抑制吸合瞬态 |
| 7 | 接线与搭建耗材 | 1 套 | 可插拔端子（凤凰端子 / JST-XH）+ 洞洞板/面包板 + 杜邦线 + 导线 | 泵阀接线便于更换 |
| 8 | 安全与指示 | 1 套 | 急停按钮（自锁、常闭）×1 + 状态 LED ×1 + 1 kΩ 电阻 | 急停独立于软件，安全冗余 |

**可选（P1 预留，不阻塞）**

| # | 物料 | 数量 | 建议规格 | 备注 |
|---|------|------|----------|------|
| 9 | 液体管路 | 若干 | 硅胶 / PharMed 类软管 + 快插/三通接头 | 生物实验注意材质相容与可灭菌 |
| 10 | 传感器（预留） | 1 套 | 温度 DS18B20 + 光电液位 / 霍尔流量计 | P1 预留接口，为日后闭环准备 |

#### 电流预算（USB 5V）

| 负载 | 典型电流 | 说明 |
|------|----------|------|
| 蠕动泵 ×2 | 约 150–300 mA / 台 | 视流量与背压 |
| 5V 电磁阀 ×3 | 约 150–300 mA / 个 | **吸合瞬时冲击更高** |
| ESP32 开发板 | 约 150–250 mA | Wi-Fi 开启瞬时更高 |
| **峰值合计** | **可能 > 1 A** | 因此建议 5V/2A 适配器，勿用普通 USB 口 |

> 电磁阀吸合瞬态电流大，务必留电源余量，并在阀就近加 100–470 µF 电解电容。#1 与 #4 是唯一"必须先买"的两件，其余可随流路确定后陆续补。

### 2.8 待确认项与风险

1. **流路参数未定**：所需流速、剪切力、死体积 → 直接决定泵型与管径（**最高优先级待确认**）。
2. **阀的介质相容性**：细胞实验要求生物相容、可灭菌；需确认阀体/膜片材质。
3. **蠕动泵软管**：材质（如 PharMed BPT 类）与灭菌/更换周期。
4. **气泡与死体积**：影响代谢物浓度读数，需在流路设计中控制。
5. **三通阀 vs 双二通阀组合**：本方案倾向后者（易采购、易维护），待确认。
6. **电磁干扰**：泵阀与电化学采集共用电源/地，可能引入噪声 → P2 联调重点。
7. **是否需要压力/流量闭环**：若需要，P1 需预留传感接口与 ADC 采样。

## 3. P2–P4 概要（本方案不展开）

### P2：主从协议打通 + 主机调度

- 主机侧实现协议状态机：`IDLE → CIRCULATE → STOP_FLOW → MEASURE →（周期）CALIBRATE`
- 三通阀拓扑逻辑：检测模式 / 校准模式切换，校准残液独立排废；保证"校准液不碰细胞、培养液不进检测回路"
- 快插/在线换电极：流路隔断支路，更换检测模块不中断培养
- 自适应校准：以基线漂移、灵敏度斜率、噪声水平为判据，动态调整校准间隔
- 安全联动：主机对从机心跳监控、故障统一处理

### P3：网页 UI 与数据分析（可在 P2 期间并行）

- **资源本地化**：改分区表扩大 SPIFFS，用轻量库（uPlot）替代 Plotly，移除 CDN 依赖
- **UI 美化**：统一设计变量（配色/圆角/间距）、响应式导航、卡片式布局、统一按钮/表单/状态徽标
- **新增入口**：`Sweep | 流体控制/协议 | 数据分析 | 历史记录 | Panel | Setup | Download | System | Help`
- **数据分析页**：多曲线叠加、缩放游标；峰检测、峰电流/峰电位、基线扣除、均值/标准差；导出 CSV/图
- **历史记录**：浏览器 IndexedDB 存每次扫描（时间/参数/署名/数据），支持回看/重命名/导入导出
- **系统页增强 + 操作日志/署名**：设备写 `log.txt`（时间/实验/参数/署名），多人可查

### P4：云端 AIoT（后续，暂不上云）

- 监测与校准数据上云、远程查看、异常告警
- 从机 ESP32 预留 Wi-Fi，可独立成网关
