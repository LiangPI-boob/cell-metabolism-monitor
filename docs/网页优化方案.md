# 网页优化方案

> 版本：v1.2
> 日期：2026-10-25
> 状态：P0（结构合并）、P1（样式统一）、P2（图表本地化 + 双网络模式）均已实施
> 范围：`data/` 目录下全部网页、样式、脚本（不改动采集算法与从机协议）
> 目标：**去臃肿、并入口、统一风格、规范格式**，保持功能等价

---

## 0. 结论摘要

| 项目 | 现状 | 优化后 |
|------|------|--------|
| 页面数量 | 12 个 HTML（10 个在用） | **4 个**：`index / setup / system / help` |
| 导航 | 6 个一级 + 4 个下拉 = 10 个入口 | **4 个一级，无下拉** |
| 样式 | `nanostatstyle.css` + 每页内联 `<style>` + Bootstrap 类混用 | **单一 `assets/app.css`**，无内联样式 |
| 脚本 | 4 个 JS，两套 WebSocket 客户端并存 | **1 套 WS 客户端 + 页面级模块** |
| 外部依赖 | Plotly ×10、Chart.js ×10、jQuery、Google Fonts、Bootstrap | **零外链**：uPlot 1.6.31 本地化（约 50 KB，随 SPIFFS 下发） |
| 首页职责 | `index.html`（扫描）与 `panel.html`（面板）功能重叠 | **合并为「控制台」单页** |
| 网络访问 | 仅 `192.168.4.1` 提示 | **热点直连 / 路由模式双通道**，页面顶部提示条自动区分 |
| 固件改动 | — | **4 处**：3 处跳转字符串 + 新增 `/netinfo` 网络状态接口 |

核心判断：**当前网页最大的"臃肿"不是 HTML 行数，而是每页都在加载约 3.5 MB 的外网图表库，并且设备工作在无外网的 SoftAP 场景。** 结构合并与依赖精简必须一起做，否则只是把混乱换个位置。

| `panel.html` | 15.4 KB | 实验流程 + 电化学参数 + 实时示波 | 约 200 行内联 CSS；与首页职责重叠 |

| `template.html` | 4.7 KB | 新页面模板 | **未使用**，但样式本身也是旧风格 |
| `wifi_index.html` | 5.0 KB | WiFi 门户首页 | 与 `wifi.html` 重复，仅被已注释的路由引用 |

脚本：

| 文件 | 体积 | 问题 |
|------|------|------|
| `websocketcode.js` | 15.7 KB | 首页专用；`doSend()` 引用未定义变量 `websocket`；含大量注释死代码 |
| `websckt_ctl_pan_LMP91000.js` | 19.3 KB | 面板专用；与上者各自建立 WS 连接 |

| `wifimanager.js` | 3.8 KB | 依赖 jQuery；`$('form').submit` 全局劫持表单 → `/edit` |

### 1.2 首页与面板的重叠（逐项对照）

| 能力 | `index.html` | `panel.html` | 结论 |
|------|--------------|--------------|------|
| 当前扫描模式显示 | ✅ `sweep_mode_id` | ✅ 同名 ID（只是放在状态行里） | 重复 |
| TIA 增益设置 | ❌（在 setup） | ✅ 运行时可调 | 保留在控制台 |
| 设定电压 | ❌（在 setup） | ✅ 运行时可调 | 保留在控制台 |
| 曲线显示 | ✅ I–V、I–t 两张 | ✅ I–t / V–t 双轴一张 | 重复，合并为一个图区 + 视图切换 |
| 模式启停 | ✅ 9 个按钮 | ✅ 启用/停用实时监测 | 语义不同，需在控制台分两个区块 |
| 实验流程控制 | ❌ | ✅ 启动/停止/阶段/周期 | 只在面板 |
| 数据保存 | 自动触发 `/downloadfile` | ✅ 文本框 + 浏览器下载 | 统一为「保存 / 下载」两个明确动作 |
| WebSocket 连接 | `websocketcode.js` | `websckt_ctl_pan_LMP91000.js` | **同一页面只能存在一个连接** |

结论：两者不是简单重复，而是**同一条工作流的两个断片**——用户要先在首页点扫描、再跳到面板看状态。合并后按「实验流程 / 手动扫描 / 实时曲线」三个区块组织。

### 1.3 五个核心问题

1. **入口割裂**：手动单次扫描在首页，自动实验流程在面板，状态与操作分居两页。
2. **依赖过重且与使用场景冲突**：10 个页面加载 Plotly（约 3.5 MB）、10 个页面加载 Chart.js（从未使用）、`files.html` 额外加载 jQuery。设备常以 `NanoStatAP` 热点独立工作，**手机连热点时没有外网，CDN 全部失败**——页面变成无样式纯文本、图表空白。
3. **视觉不统一**：`body` 用浅蓝 `hsl(216,99%,90%)`，面板另起一套 `--ns-*` 变量覆盖；`setup.html` 用 `mybox1–7` 彩色底块；品牌字体用 Leckerli One，正文无统一字体；9 个页面英文、1 个页面中文。
4. **格式不规范**（有据可查）：
   - 每页复制粘贴同一段导航（约 45 行），共 10 份；
   - 大量 `style="..."` 内联样式；
   - `setup.html` 中 `sweep_param_vertex2_CV` 复用了 `sweep_param_vertex1_CV_id`、`setToZero_id` 重复出现；
   - `<form ... enctype="application/json">`（非法编码类型，浏览器按 urlencoded 提交）；
   - `files.html` 表单缺少 `</FORM>`；
   - `<script type="text/javascr" src="plotlyplot.js">`（类型拼错且文件不存在）；
   - 全部页面 `<title>NanoStat</title>`，无法区分标签页；
   - `aria-table` 应为 `aria-label`；
   - 各页 `<h1>` 直接写在 `<header class="container">` 里，缺页面级结构语义。
5. **死文件与死代码**：`template.html`、`wifi_index.html` 无路由引用；`plotlyscope.js` / `plotlyplot.js` 不存在；`setup.html` 的 `xyz` 注释块约 100 行。

## 2. 目标结构

### 2.1 页面地图（10 → 4）

| 新页面 | 职责 | 合并来源 | 默认入口 |
|--------|------|----------|----------|
| `index.html` | **控制台**：实验流程 + 手动扫描 + 实时曲线 + 数据导出 | `index.html` + `panel.html` + `download.html` | ✅ |
| `setup.html` | **参数**：通用参数 + 8 类扫描模式参数 | `setup.html` | |
| `system.html` | **系统**：文件 / WiFi / 固件 / 重启（Tab 切换） | `files.html` + `wifi.html` + `firmware.html` + `reboot.html` | |
| `help.html` | **帮助**：使用说明 + 模式解释 + 关于/引用 | `help.html` + `about.html` | |

删除：`panel.html`、`download.html`、`files.html`、`wifi.html`、`firmware.html`、`reboot.html`、`about.html`、`template.html`、`wifi_index.html`。

### 2.2 导航（4 项，统一中文）

```
NanoStat        控制台   参数   系统   帮助
```

- 去掉 `System` 下拉，四项平铺，移动端折叠为汉堡菜单；
- 当前页通过 `.is-active` 高亮，不再用 Bootstrap 的 `active`；
- 导航块只存在一份，在每页固定位置，**不允许各自改文案**。

### 2.3 控制台（`index.html`）线框

```
┌──────────────────────────────────────────────────────────┐
│ 状态条：● 已连接  ● 从机在线  |  模式 IDLE  |  阶段 --    │
├───────────────────────────────┬──────────────────────────┤
│ ① 实验流程                     │ ④ 实时状态               │
│   阶段 / 周期 / 校准倒计时      │   扫描模式               │
│   ● 循环泵  ● 切换阀  ● 排废阀  │   LMP 百分比 / DAC       │
│   [启动实验] [停止实验]         │   ADC (bit / mV)          │
│                                │   平均电流 / 标准差       │

│                                │                          │
│ ③ 手动扫描                     │                          │
│   [CV][NPV][DPV][SWV][CA]      │                          │
│   [DC][IV][Cal][Misc]          │                          │

├───────────────────────────────┴──────────────────────────┤
│ ⑤ 实时曲线   [I–t] [I–V]                      高度 ≥320px │
│   ┌──────────────────────────────────────────────────┐   │
│   │                                                  │   │
│   └──────────────────────────────────────────────────┘   │
│   [保存数据] [下载 data.txt]                              │

```

要点：

- **状态条横跨顶部**，把原先散落在首页/面板的「连接、从机、模式、阶段」集中到一处；
- **操作区与状态区左右分栏**，768 px 以下自动单列；
- **手动扫描**保留 9 个按钮（含 `Misc`），每个分组标题右侧放「参数 →」链接跳 `setup.html#cv`；
- **实时曲线**只有一个 DOM 容器，用 Tab 切换 I–t / I–V，避免同页两套绘图对象；
- **数据导出**只保留两种明确动作，去掉"扫描完自动 `window.open('/downloadfile')`"这种隐式行为。

### 2.4 参数页（`setup.html`）重排

- 顶部：`General`（TIA 增益、结束时归零）常驻显示；
- 其余 8 组改为**折叠面板**，默认收起，标题显示每组参数个数：CV / NPV / DPV / SWV / CA / IV / DC Noise / Calibration；
- 每组内部统一为「标签 + 输入框」两列网格，不再用彩色块；
- 提交行为不变：`POST /actionpage.html`，字段 `name` 全部保持原值；
- 增加「恢复默认值」（`type="reset"`）与「提交」（右下角固定按钮条）。

### 2.5 系统页（`system.html`）Tab

| Tab | 内容 | 对应后端接口 |
|-----|------|--------------|
| 文件 | 上传、目录列表、删除 | `/m_fupload`、`/list`、`/edit`(DELETE) |
| WiFi | 凭据保存、扫描列表 | `/saveSecret`、`/wifiScan.json` |
| 固件 | 固件 / 文件系统烧写 | `/m_firmware_update`、`/m_filesystem_update` |
| 重启 | 二次确认 + 重启按钮 | `/rebootnanostat` |

Tab 用纯 CSS/原生 JS 实现，不引入组件库。**危险操作（OTA、重启、删除）统一为红色按钮 + 确认提示。**

### 2.6 帮助页（`help.html`）

- 使用流程：上电 → 连接热点 → 打开控制台 → 启动实验；
- 每种扫描模式一段说明（沿用现有英文内容并译为中文，保留 BAS 教程外链）；
- 附「关于」：项目引用、GitHub 链接、固件版本；
- 去掉远程头像图片与 Font Awesome。

### 3.1 设计令牌（`assets/app.css` 顶部 `:root`）

| 令牌 | 值 | 用途 |
|------|----|------|
| `--bg` | `#f5f7fa` | 页面底色（统一，替换浅蓝） |
| `--surface` | `#ffffff` | 卡片底 |
| `--text` | `#1f2937` | 正文 |
| `--muted` | `#6b7280` | 次要文字 |

| `--primary` | `#2563eb` | 主操作 |
| `--ok` | `#16a34a` | 在线 / 运行 |
| `--warn` | `#d97706` | 警告 |
| `--danger` | `#dc2626` | 危险 / 离线 |
| `--radius` | `12px` | 卡片、按钮 |
| `--space` | `4px` 基准 | 间距 4/8/12/16/24 |
| `--shadow` | `0 1px 2px rgba(16,24,40,.05)` | 仅卡片 |

字体：`system-ui, -apple-system, "Segoe UI", "Microsoft YaHei", sans-serif`；数字与曲线轴使用 `ui-monospace, Consolas, monospace`。**移除 Leckerli One、Roboto、Google Fonts、Font Awesome。**

### 3.2 组件（全部自定义，约 300 行 CSS）

| 组件 | 类名 | 说明 |
|------|------|------|
| 卡片 | `.card` / `.card__head` / `.card__body` | 替代 `mybox*` 与 `ns-card` |
| 状态徽标 | `.badge` + `.badge--on` / `--off` | 替代 `ns-badge` |
| 按钮 | `.btn` + `.btn--primary` / `--ghost` / `--danger` | 单一尺寸体系，去 `btn-sm` 之类多套 |
| 字段 | `.field` / `.field__label` | 替代 `form-box` / `ns-field` |
| 指标 | `.stat` / `.stat__k` / `.stat__v` | 替代 `ns-stat` |
| 行状态 | `.kv` / `.kv__k` / `.kv__v` | 替代 `ns-row` |
| Tab | `.tabs` / `.tabs__btn` / `.tabs__panel` | 控制台曲线、系统页共用 |
| 提示条 | `.hint` / `.hint--warn` | 替代散落的 `small text-danger` |

### 3.3 栅格与响应式

- 使用 CSS Grid：`.grid--2`（两列）、`.grid--3`（三列），`gap: 16px`；
- 断点：`@media (max-width: 820px)` 全部降为单列；
- 图表容器 `min-height: 320px`；移动端允许横向滚动的最小宽度 320 px；
- 不再使用 Bootstrap 的 `container / row / col-*`。

### 3.4 依赖策略（已确认：方案 A）

| 方案 | 做法 | 优点 | 代价 |
|------|------|------|------|
| **A（推荐）** | 自写 CSS；图表仅首页保留 Plotly（CDN，加载失败显示提示条） | 改动可控，保留缩放/导出等交互 | 首页仍依赖外网 |
| **B** | 图表换 uPlot（约 50 KB）放入 SPIFFS | 完全离线可用，体积降 98% | 需重写两套绘图逻辑，交互简化 |

建议：**P0/P1 按 A 做，P2 切 B。**

> 最终结论（P2 已实施）：采用方案 B。`assets/uplot.min.js`（50 KB）+ `assets/uplot.min.css`（2 KB）随 `uploadfs` 一起进 SPIFFS，`index.html` 不再引用任何 CDN；全站 `data/` 合计约 128 KB，远低于默认 SPIFFS 分区 1.5 MB。图表库缺失时页面显示提示条，采集、控制、下载不受影响。

### 3.5 网络模式提示条（P2）

设备本就运行 `WIFI_AP_STA`：SoftAP「NanoStatAP」常开，同时可加入路由器。两种访问方式对应两套地址，需要让用户随时知道自己在哪一侧：

| 模式 | 判定依据 | 提示条 |
|------|----------|--------|
| 热点直连 | `location.hostname === ap_ip`（默认 `192.168.4.1`） | 蓝色，标签「热点直连」；若设备已连路由器，附路由器 IP |
| 路由模式 | 主机名不等于 AP 地址（`nanostat.local` 或路由器 IP） | 绿色，标签「路由模式」；显示当前地址与热点仍可直连的提示 |

实现要点：

- 固件新增 `GET /netinfo`，返回 `ap_ssid / ap_ip / ap_clients / sta_connected / sta_ssid / sta_ip / sta_rssi / mdns`；
- `app.js` 在 `DOMContentLoaded` 时请求 `/netinfo`，失败或 404 时回退为「未连路由器」文案，不阻塞页面；
- 四个页面都在 `</body>` 前引入 `app.js`，提示条插在 `nav.nav` 之后，样式为 `.netbar / .netbar--ap / .netbar--sta`；
- 提示条右侧「网络说明」跳到 `help.html#network`，帮助页给出两种方式的完整对照。

## 4. 文件与代码规范

### 4.1 目录结构

```
data/
├── index.html          # 控制台
├── setup.html          # 参数
├── system.html         # 系统
├── help.html           # 帮助
├── assets/
│   ├── app.css         # 全部样式（唯一）
│   ├── app.js          # 导航、Tab、徽标、网络提示条、唯一 WebSocket
│   ├── console.js      # 控制台：WS + 状态 + uPlot 图表
│   ├── system.js       # 系统页：文件/WiFi/OTA
│   ├── uplot.min.js    # 本地图表库（uPlot 1.6.31）
│   └── uplot.min.css   # 图表库样式
```

### 4.2 统一页面骨架

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>

  </nav>

  <main class="page">
    <header class="page__head">
      <h1>控制台</h1>
      <p class="page__sub">LMP91000 电化学检测 + 流体控制</p>
```

规则：

- `lang="zh-CN"` 全站统一；
- `<title>` 格式固定为 `NanoStat · 页面名`；
- 导航块 6 行，直接复制，**内容逐字一致**；
- CSS 在 `<head>`，脚本放在 `</body>` 前，`defer` 可省。

### 4.3 命名规范

| 类型 | 规则 | 示例 |
|------|------|------|
| CSS 类 | `ns` 前缀省略，用 BEM 简化式：`block__element`、`block--modifier` | `.card__head`、`.badge--on` |
| HTML id | kebab-case，`区块-用途` | `exp-state`、`pump-dot` |
| JS 函数 | camelCase，动词开头 | `connectWs()`、`renderExpState()` |
| JS 常量 | UPPER_SNAKE | `WS_URL`、`MAX_POINTS` |
| 文件 | 全小写、短横线 | `console.js` |

禁止：内联 `style`、`myboxN` 这类无语义类名、`xxx_id` 后缀式 id、`onclick="on_Button_3_pressed()"` 这类散装全局函数。

### 4.4 JS：单一 WebSocket 连接 + 消息路由

合并页的最大技术风险是**两套 WS 客户端同时存在**：`websocketcode.js` 期待二进制数组，`websckt_ctl_pan_LMP91000.js` 期待 JSON，二者都会调用 `Plotly.newPlot` 且重复绑定全局变量。方案：

```js
// assets/app.js —— 唯一连接入口
const WS_URL = `ws://${location.hostname}:81/`;
const bus = new EventTarget();          // 消息总线
let ws = null, retry = 1000;

function connectWs() {
  ws = new WebSocket(WS_URL);
  ws.binaryType = 'arraybuffer';
  ws.onopen = () => bus.dispatchEvent(new Event('ws:open'));
  ws.onclose = () => { bus.dispatchEvent(new Event('ws:close')); setTimeout(connectWs, retry); };
  ws.onmessage = (e) => {
    if (typeof e.data === 'string') {
      let msg; try { msg = JSON.parse(e.data); } catch { return; }
      bus.dispatchEvent(new CustomEvent('ws:json', { detail: msg }));
    } else {
      bus.dispatchEvent(new CustomEvent('ws:bin', { detail: e.data }));
    }
  };
}

function wsSend(obj) {
  if (ws && ws.readyState === WebSocket.OPEN) ws.send(JSON.stringify(obj));
}
```

```js
// assets/console.js —— 只订阅，不建连接
bus.addEventListener('ws:json', (e) => {
  const m = e.detail;
  if ('exp_state' in m) renderExp(m);
  if ('slave_link' in m) renderLink(m.slave_link);
  if ('is_sweeping' in m) renderSweep(m.is_sweeping);
  if ('Voltage' in m) drawIV(m);        // 文本波形
});
```

约束：

- 全站**只允许 `app.js` 调用 `new WebSocket`**；
- 页面对 WS 一律"订阅事件"，不直接持有 socket；
- 参数下发统一走 `wsSend({ key: value })`，键名与固件 `handle_websocket_text()` 保持一致，**不改协议**。

### 4.5 CSS 规范

- 只用 class 选择器，禁止 `#id` 参与样式；
- 颜色、圆角、阴影必须用 `var(--x)`，禁止硬编码色值；
- 文件内按「复位 → 令牌 → 布局 → 组件 → 页面局部」五段注释分区；
- 页面局部样式不超过 30 行，超出说明组件缺失，应抽到组件段。

### 4.6 清理要求

- 不保留注释掉的 HTML/JS 大段代码（如 `setup.html` 的 `xyz` 块）；
- 不引用不存在的文件（`plotlyplot.js`、`plotlyscope.js`）；
